# 想起 v2.3 — ComfyUI 出力台帳 ＋ キャラ帳

ComfyUI が出力した PNG に埋め込まれているワークフローを読み取って台帳にし、
ブラウザから絞り込んで **ComfyUI にそのまま再投入する** 道具です。
v2 では、絵に写っている子を見分けて名前を付ける **キャラ帳** を一から作り直しました。

---

## v2.3 で変わったこと — 差し替えに服装・保存名のひな形・生成中の投入

**v2.2 からは上書きするだけです。**

- **生成中でも投入できる** … 前は、画像を開いた瞬間に ComfyUI の返事が遅れていると（生成中、とくにモデルの読み込み中に起きる）、
  投入ボタンが押せないまま戻りませんでした。ボタンは常に押せるようにし、右上の表示を
  「待機中・キュー N ／ 返事待ち（生成中かも）／ 未接続」の 3 段にしました。投入は 120 秒まで返事を待ちます。
- **割り込み** … 「割り込み（キューの先頭へ）」にチェックすると、今の生成の次に回ります。
- **保存名のひな形** … 投入するときの保存名（SaveImage の filename_prefix）を
  `%date:yyyy%-%date:M%-%date:d%/%date:yyyy%-%date:M%-%date:d%illu{キャラ}` で付けます。
  {キャラ} には、差し替えたときは差し替え先の名前、普通の投入ではその絵のキャラの名前が入ります。
  キャラが分からない絵（未分類・確認待ち）や 2 人写っている絵は、投入する前に名前を聞きます。
  保存の欄が 2 つあるワークフロー（拡大前と拡大後など）は、`_up` のような後ろの付け足しを残して名前だけ入れ替えます。
  ひな形はキャラ帳の **設定 → 保存名のひな形** で変えられます。「保存名をひな形にそろえる」を外すと、元の保存名のまま投入します。
- **服装** … 差し替えの欄で服も選べます（下の「キャラ・服を差し替える」）。キャラはそのまま服だけ替えることもできます。
- **差し替えの強さ** … 「体格・年齢・種族まで」（今までどおり）と「髪と目だけ」。
- **できた絵に画面用のワークフローも入る** … 前は、想起から投入してできた絵には API 用の形しか入っておらず、
  あとで ComfyUI に開くと配置が崩れていました。差し替えや保存名を反映した画面用のワークフローも一緒に送るようにしました。

## v2.2 で変わったこと — 投入したワークフローが ComfyUI の画面に出る

**投入ボタンを押すと、同じワークフローが ComfyUI の画面にも新しいタブで開きます。**
プロンプトを少し手直ししてもう一度回したいときに、「WF」で取り出してドラッグする手間がなくなります。

- 投入しないで開くだけなら **「ComfyUI の画面で開く（投入しない）」**
- キャラの差し替えも **「差し替えて ComfyUI の画面で開く（投入しない）」** で、差し替えた状態のまま開けます
- 保存先の日付を今日にする設定も、開いたワークフローに反映されます
- ComfyUI が受け付けなかったとき（モデルが見つからない等）も開くので、その場で直して回せます

これには、ComfyUI に **想起の受け口（souki_bridge）** を 1 回だけ入れる必要があります（下の「最初の 1 回」）。
ノードは増えず、Python の部品も入れません。

### 最初の 1 回

1. ComfyUI を起動した状態で想起の台帳を開き、画像を 1 枚開く
2. 投入ボタンの下の **「受け口を入れる」** を押す
   （ComfyUI に custom_nodes の場所を聞いて、`custom_nodes\souki_bridge` を置きます。
   見つからないときは場所を聞かれるので、`…\ComfyUI\custom_nodes` を入れてください）
3. **ComfyUI を再起動** して、ブラウザの ComfyUI の画面も読み直す

手で入れる場合は、想起のフォルダの `comfyui_node\souki_bridge` を ComfyUI の `custom_nodes` へ写して再起動します。
受け口が入っていないうちは、前と同じく ComfyUI のワークフロー一覧に保存します。

ComfyUI の画面が開いていないときに押すと、ComfyUI の画面を新しく開いて、そこに読み込みます。
ブラウザのタブは自動では切り替わらないので、ComfyUI のタブに切り替えてください。

## v2.1 で変わったこと — 何万枚もの候補を片付けるために

v2.0 を 12 万枚で使っていただいて出た 4 つの問題を直しました。
**v2.0 からは上書きするだけです。付けた名前・確定・否はそのまま引き継ぎます**（環境の作り直しもありません）。

| | v2.0 | v2.1 |
|---|---|---|
| ① 動作が遅い | 画面を開くたび・操作のたびに待たされる | ほとんどの操作が 1 秒以内（「6. 検証状況」の表）。遅かった原因は下に |
| ② 並べ替え | 並びが決まっていて、数千枚を 1 枚ずつ目で追うしかない | **並べ替え**（似た顔ごと・怪しい順・新しい順・古い順・ファイル名順 など）と **かたまり表示** |
| ③ 範囲選択 | 顔と顔の **すき間** からしかドラッグを始められない | **顔の上からでも** ドラッグで囲める。画面の端へ寄せると自動で送る |
| ④ さらに表示 | 50 枚ずつ | **ページ送り**（1 ページ 100 / 300 / 600 / 1000 枚）。付けた × はページをまたいで残る。**「全部」を × 以外まとめて確定** |

**遅かった主な原因** は 2 つでした。

- 画面の状態を問い合わせるたびに、**前の版の顔の切り抜きフォルダ**（何万ファイル）を数え直していた。
  → 起動したときに裏で 1 回だけ数えるようにしました。
  前の版のデータは **設定 → 前の版のデータ** から消せます（消すとディスクも空きます）。
- 名前を付けるたびに、機械の判定を **全部書き直していた**。→ 変わった行だけ書くようにしました。

ほかにも、判定・候補づくり・一覧の表示を全体に速くしています。
遅いと感じる所が残っていたら、**設定 → 速さの記録** の表を写して知らせてください。

## まず読んでください — v2 で変わったこと

**起動は `起動.bat` ひとつです。** 前の版と同じ名前なので、ショートカットはそのまま使えます。
初回だけ、専用の Python 環境を自動で用意します（3〜10 分、回線が要ります）。

| | 前の版 | v2 |
|---|---|---|
| 顔の見分け | 顔の検出 ＋ 汎用の画像特徴でクラスタ | **頭部検出 ＋ CCIP**（アニメキャラの同一判定専用モデル） |
| 名前の付け方 | クラスタに名前 → 混ざったら健康診断 | 候補に名前 → 残りは機械が判定、迷った顔だけ「確認待ち」 |
| 混ざり | 固定の線（0.55）が背景の近さ（0.572）より下にあり、別の子を吸い込んだ | 見本は **人が確定した顔だけ**。線は厳しくする向きにしか動かない |
| Python | ComfyUI の Python などを探して使う（CUDA 版が要る） | `runtime` に専用の Python 3.12。**ComfyUI の Python には何も入れない** |
| GPU | CUDA（RTX 5080 で動くか不確か） | **DirectML**（Windows 標準。DirectX 12 対応 GPU ならどれでも） |
| 起動 | bat が 5 つ | `起動.bat` だけ |

- **前の版で付けた名前は引き継ぎません**（ご指定どおり、まっさらからやり直します）。
  **台帳（画像の記録・サムネイル・検索・再投入）はそのまま使えます。**
- 前の版の部品（`kao.py`、`キャラ解析.bat`、`台帳を更新.bat` など）は、
  起動したときに **`_旧版` フォルダへ移します（消しません）**。
- 前の版のデータ（顔クラスタの記録、顔の切り抜き）は台帳とは別です。
  キャラ帳の **設定 → 前の版のデータ** から消せます。消さなくても動作には影響しません。

## 1. 入れ替えかた

1. 想起の窓を閉じる
2. zip の中身を、いまの想起のフォルダに **上書き** する
   （`config.json` は入っていません。出力フォルダの設定はそのまま残ります）
3. `起動.bat` を開く

v2.0 からの入れ替えは、これだけです（下の初回の準備は v2.0 で済んでいるので、すぐ起動します）。
起動した直後の十数秒は、顔の特徴を読み込むために右上に「判定中」と出ます。

初回は次のように進みます。

```
起動.bat
 └ 専用の Python 環境がない → setup\setup.bat を自動で呼ぶ
     [1/4] uv（Python の管理ツール）を取ってくる       GitHub、だめなら PyPI
     [2/4] 専用の Python 3.12 を用意する               runtime\python
     [3/4] numpy / pillow / onnxruntime-directml を入れる（版を固定）
     [4/4] キャラ判定のモデル（約 200MB）を取ってきて、GPU を試験する
 └ 台帳のサーバを起動して、ブラウザを開く
```

2 回目からはすぐ起動します。起動するたびに出力フォルダを読み直します
（変わったファイルだけを読むので数秒です）。

## 2. キャラ帳の使いかた

台帳の画面の右上 **「キャラ」**、または `http://127.0.0.1:8765/chara` で開きます。
上の帯に **解析 / 候補 / キャラ / 確認待ち / 未分類 / 設定** が並びます。

### 最初の 1 回（解析の画面が案内します）

1. **準備** — モデルの取得と GPU の試験。`起動.bat` の初回で済んでいるはずです。
   失敗していたら「準備する」を押します。
2. **試運転** — 500 枚だけ解析して、次を測ります（数分）。
   - 1 枚あたりの速さと、**全件の見込み時間**
   - 要平さんの絵でどれくらい見分けられているか
   - 絵全体で見るか、上半身で見るか（おすすめを出します）
3. **全件を解析** — 途中で止めても、次に押すと続きから再開します。
   解析中も台帳や ComfyUI はふだんどおり使えます。
4. **候補に名前を付ける**（下へ）

全件を一度済ませたあとは、台帳を更新したときに **新しい絵だけ自動で解析** します
（設定で止められます）。

### 候補に名前を付ける

「候補」は、名前の付いていない顔のうち **同じ子らしいまとまり** です。大きい順に並びます。
何万枚もある候補は、1 枚ずつ見るのではなく **「かたまり」で見て、違う所にだけ × を付け、残りをまとめて確定** します。

1. 候補を開く。500 枚以上ある候補は **かたまり表示** で開きます
   - 候補の中を、さらに **似た顔のかたまり**（数十〜数百枚ずつ）に分けて、かたまりごとに見本を 1 列並べます
   - **怪しいかたまりから** 並びます（候補の芯から遠い＝別の子が混ざりやすいものが上）
2. 違う子のかたまりに **「× 違う」**。かたまりの中を確かめたいときは **「開く」**
3. 名前を入れて、範囲を **「全部」** にして **「× 以外を確定」**
   - × の顔は **「この子ではない（否）」** として覚えます
   - すでにいるキャラの名前を入れれば、そのキャラに足されます
     （同じ子が絵柄違いで 2 つの候補に分かれることがあります）
4. × の顔が残ったときは、その顔だけが並んだ画面になります。別の子なら名前を付けて確定、
   いなければ「見送る」、あとで決めるなら「次の候補へ」

**1 枚ずつ見たいとき** は「1 枚ずつ」に切り替えます。

- **並べ替え** … 似た顔ごと（怪しいかたまりから）／怪しい順／代表的な顔から／新しい順／古い順／ファイル名順（日付フォルダ順）
- **1 ページの枚数** … 100 / 300 / 600 / 1000 枚。`←` `→`（`PageUp` `PageDown`）でページを送る
- **印の付け方**
  - クリックで ×、`Shift` を押しながらクリックで範囲
  - **ドラッグで囲む**（顔の上からでも、すき間からでも始められます）。
    最初に触った顔に × が無ければ付ける、あれば外す。`Alt` を押しながらだと外す。
    画面の上下の端へ寄せると自動で送ります
  - `Ctrl+A` でこのページ全部に ×。「× を全部外す」もあります
  - × はページを移っても残ります
  - 右クリックで、その顔の元の絵と詳しい情報
- **範囲** … 確定する範囲を選びます
  - **このページ** … 見ているページの × 以外
  - **1〜N ページ** … 最初のページから見ている所までの × 以外（見た所まで確定）
  - **全部** … まだ見ていないページも含めて × 以外全部

一度きりの子ばかりの候補は **「見送る」** で候補から外せます（未分類の「見送った顔」から戻せます）。
候補の手がかりに **「髪がばらばら — 別の子が混ざっているかも」** と出ているものは、特に注意して見てください。

名前を付けると、その子の残りの絵は機械が判定します。**自信のある顔だけ「自動」で入り、
迷った顔は「確認待ち」に回ります。**
「全部」で確定して見ていない顔に間違いが混ざっても、あとでキャラの画面の **「浮いている」** に出てきます。

### 確認待ちを片付ける

機械が迷った顔が、キャラごとに **枚数・迷った理由・見本** でまとまって出ます。
**「片付ける」** を押すと、そのキャラの画面の「確認待ち」が開きます。候補と同じように
**違う顔にだけ × を付けて「× 以外を確定」** してください（並べ替え・かたまり・範囲も同じです）。
決めた分だけ見本が増え、次からは自動で入る顔が増えます。

顔の左下に迷った理由が出ます。

| 理由 | 意味 |
|---|---|
| 複数のキャラに近い | 2 人以上のキャラに十分近い。どちらか決められない |
| やや遠い | 自動の線より少し遠い。本人の珍しい絵柄か、そっくりな別の子 |
| 特徴語が食い違う | 顔は近いが、プロンプトの髪色・目の色・ツノなどがそのキャラの書き方と違う |
| 色が違う | 顔は近いが、頭のまわりの色がそのキャラのふだんの色と違う |
| 否に近い | 「この子ではない」とした顔のほうが近い |
| LoRAと食い違う | 別のキャラの LoRA を使っている絵 |
| 見本が少ない | 近い見本が 1 枚しかない |

### キャラの画面

キャラを開くと、タブで **確定 / 自動 / 確認待ち / 否 / 浮いている** を見られます。

- **確定** … 人が確定した顔。判定の見本です。間違いを選んで「この子ではない」「別のキャラへ」「未分類に戻す」
- **自動** … 機械が入れた顔。「遠い順（怪しい順）」で並べて、違う顔に × →「× 以外を確定」
- **確認待ち** … 機械が迷った顔。自動と同じく × →「× 以外を確定」
- **否** … 「この子ではない」とした顔。「やっぱりこの子」「否を取り消す」
- **浮いている** … 確定した顔のうち、ほかの確定から大きく離れている顔（うっかり確定の見直し用）。
  違う顔に × を付けて「× 以外はこの子」。出ているときだけタブが出ます

**全部に × を付けて押すと「全部この子ではない」** として覚えます（確認待ちに、その子が 1 枚もいないとき）。ボタンの表示が「× を全部「名前」ではないにする」に変わります。候補の画面でも、すでにいる名前なら同じことができます。

どのタブも、候補と同じく **並べ替え・かたまり表示・ページ送り・範囲** が使えます。
何万枚も確定したキャラでも、かたまり表示にすれば混ざった顔を見つけやすくなります。

上の欄では次のことができます。

- **名前** をクリックで改名
- **書き分け** … 確定した 1 人の絵のプロンプトから見た、その子の髪・目・ツノなど。
  太字のものは「確かな書き分け」で、食い違う絵は自動では入れません
- **差し替えで入れる特徴語** … 台帳の「キャラを差し替える」で使う語。直して保存できます
- **統合…** … 同じ子が 2 人に分かれてしまったとき
- **LoRA 学習データ** … 確定した 1 人の絵とキャプションを `export\lora` に書き出します
- **台帳でこの子の絵を見る**

### 未分類と「似た顔」

どのキャラにも入っていない顔です。顔を選んで名前を付けられます。
**1 枚選んで「似た顔を探す」** を押すと、その顔に近い順に並ぶので、同じ子をまとめて拾えます。

### 取り消し

名前付け・確定・否・移動・統合・削除・改名は、**すべて右上の「↶ 取り消す」（`Ctrl+Z`）で戻せます**
（直近 100 回まで）。操作のすぐあとに出る知らせの「取り消す」でも同じです。

### 設定

- **解析に使う装置** … GPU ごとに CPU と答え合わせをした結果が出ます。答えの合った装置だけ選べます。
  「自動」は、GPU が 2 枚あるとき **VRAM の小さいほう（RTX 3060）** を選びます。RTX 5080 は ComfyUI に空けておくためです
- **顔の見方** … 絵全体（1 人の絵）か、上半身だけか。変えると、足りない分を解析し直してから判定します
- **新しい絵** … 台帳の更新のあとに自動で解析するか
- **出力フォルダ** … ComfyUI の output フォルダ（1 行に 1 つ）
- **判定の線** … キャラごとの自動の線と、その決め手（参考）
- **書き出し** … キャラ設定シート（HTML）と LoRA 学習データ
- **前の版のデータ** … 消すボタン（残っているときだけ出ます）
- **速さの記録** … 起動してからの、画面の問い合わせごとの時間。遅いと感じたら写して知らせてください
- **版** … 画面・部品・モデルの版

## 3. 判定のしくみ — 混ざらないための約束

前の版の混ざりは、**機械が入れた顔が見本を動かし、動いた見本がさらに別の子を吸い込む**
悪循環と、固定の線が背景の近さより下にあったことが原因でした（9/19 の健康診断で分かったもの）。
v2 はそれが構造上起きないように組んであります。

1. **見本は人が確定した顔だけ。** 自動・確認待ちの顔は見本になりません。何度判定し直しても結果は変わりません
2. **見本は 1 枚 1 枚。** 平均は取りません。カラーとマンガ調を同じ子にしても、見本が中間に落ちません
3. **線はモデルの公開値から始めて、厳しくする向きにしか動かしません。**
   別のキャラの見本や「否」にした顔が近ければ、そのキャラの線を別人が 1% も入らない所まで下げます
4. **「自動」になるのは、次を全部満たすときだけ**
   - 自動の線の内側にいるキャラが **1 人だけ**（2 人以上なら確認待ち）
   - そのキャラの見本が 2 枚以上、線の内側にある
   - 「否」にした顔のほうが近くない
   - プロンプトの特徴語が、そのキャラの確かな書き分けと食い違わない
   - 頭のまわりの色が、そのキャラのふだんの色の範囲にある
   - 別のキャラの LoRA を使っていない
5. **機械は「確定」と「否」に触りません。**

CCIP は髪色の違いに鈍い（形が同じで色だけ違う 2 人を同じに見る）ことが知られています。
そこをプロンプトの特徴語と、頭のまわりの色で補っています。

**GPU** は DirectML で使います。「GPU が見えている」と「GPU で正しく計算できる」は別の話なので、
GPU ごとに CPU と同じ答えが出るかを試験してから使います。

## 4. 台帳の画面

### 期間で絞る

上部の **TIMELINE** が月ごとの枚数です。**帯をドラッグ** するとその期間に絞られます。
左上の欄に `2026-01` `2026-03` のように直接入力もできます。`1週` `1月` `3月` `1年` は直近からの期間です。

### 似た絵を探す

画像を開いて右上の **「似た絵」** を押すと、その絵に似たものを並べます。
キャラ帳の解析が済んでいれば **顔（CCIP）で** 比べるので、「前にこんな感じの子を描いたな」から辿れます。
顔がない絵は絵柄のハッシュで比べます。

### 左の絞り込みレール

CHARACTER / CHECKPOINT / LORA / TAG / FOLDER が多い順に並びます。
クリックで絞り込み、もう一度で解除。**タグは右クリックで「除外」**。複数選ぶと AND 条件です。
CHARACTER はキャラ帳の **確定と自動** の絵を数えます（確認待ちは入れません）。

### カード左下のランプ

今の ComfyUI 環境でそのワークフローを再現できるかを、`/object_info` に問い合わせて判定しています。

| 色 | 意味 | 対処 |
|---|---|---|
| 🟢 緑 | そのまま再現できます | — |
| 🟠 橙 | モデルファイルが見つからない | 名前かパスが変わっています |
| 🔴 赤 | 必要なカスタムノードが無い | ノードを入れ直せば再現できます |
| ⚪ 灰 | 未検証、またはワークフロー情報なし | — |

### 「重複を畳む」

dHash が一致するものを 1 枚にまとめて表示します。カードの `×3` はまとめられた枚数です。

### 再投入

| モード | 動作 |
|---|---|
| **SEED ランダム** | seed だけ振り直して投入。枚数を指定すると全て別 seed |
| **完全再現** | ワークフローを一切変えずに投入 |
| **指定** | seed を手入力して投入 |

**「保存名をひな形にそろえる（日付は今日）」**（既定オン）で、保存名を設定のひな形で付けます（冒頭の「v2.3 で変わったこと」）。
外すと、元の保存名のまま投入します。**「割り込み（キューの先頭へ）」** で、今の生成の次に回せます。
**「投入したワークフローを ComfyUI の画面にも開く」**（既定オン）で、投入と同時に ComfyUI の画面に新しいタブで開きます
（受け口が要ります。冒頭の「v2.2 で変わったこと」を見てください）。
何枚投入しても、開くのは 1 つだけです。

### キャラ・服を差し替えて投入する

**構図・表情はそのままに、キャラや服を入れ替えて生成できます。**

1. 使いたい構図の画像を開く
2. **キャラ** を選ぶ（「このまま」なら服だけ替える）
3. **強さ** … 「体格・年齢・種族まで」か「髪と目だけ」
4. **服装** を選ぶ
   - 元の絵のまま
   - その子の **いつもの服** … 台帳の絵のプロンプトから、よく一緒に書かれている服の語の組を多い順に
   - **登録した服** … 名前を付けて保存した服。「この絵の服を登録…」で、開いている絵の服を保存できます。
     「その子だけ」か「どの子にも」を選べます。キャラ帳のキャラの画面の「登録した服」で一覧・削除
   - **自分で書く** … 服の語をカンマ区切りで（書いた服も「この服を登録…」で保存できます）
5. 何が外れて何が入るか（赤が外れる語、緑が入る語）と、保存名を確かめる
6. 「差し替えて投入」、または「ComfyUI の画面で開く（投入しない）」

服の語（shirt・skirt・thighhighs・hat… と、その色や状態の語）と **髪飾り（リボン・髪留めなど）** は服として扱い、
服を替えたときに入れ替わります。拾い漏れる語は `config.json` の `"outfit_words"`、服ではない語は `"not_outfit_words"` に足せます。

入れる語は、キャラ帳のそのキャラの **「差し替えで入れる特徴語」** です（自動で選んだものを直せます）。
外す側は、その画像に書かれている髪・目・ツノなどの語を表記にかかわらず外し、
台帳から「その子にだけ集中して出ている語」も学んで外します。

書き換えるのはプロンプトの文字列だけです。LoRA は触りません。
それでも漏れる語は `config.json` に足せます。

```json
"identity_words": ["独自の紋章", "特殊な瞳"],
"not_identity_words": ["blonde"]
```

### 手直ししてから流す

**「ComfyUI の画面で開く（投入しない）」** を押すと、ComfyUI の画面に新しいタブで開きます。
そのまま直して ComfyUI の「Run」で回してください。

受け口を入れていないときや、ファイルとして持っておきたいときは、画像を開いて右上の **「WF」** を押します。
`.json` がダウンロードされるので、**ComfyUI の画面にドラッグ** すれば開きます。

### キーボード

| キー | 台帳 | キャラ帳 |
|---|---|---|
| `/` | 検索欄へ | — |
| `←` `→` | 前後の画像へ | 前後のページへ（`PageUp` `PageDown` も） |
| `Ctrl+A` | — | このページ全部に印 |

## 5. 困ったとき

**起動.bat の窓に `[ERROR]` と出て止まった**
表示された内容を写して知らせてください。回線やセキュリティソフトが原因のことが多いので、
回線を確かめて `起動.bat` をもう一度開くと、続きから進みます。
準備が終わらなくても、台帳だけは PC の Python（Pillow 入り）で起動します（キャラ帳は使えません）。

**おかしくなったので専用の環境を作り直したい**
想起の窓を閉じてから `setup\環境を作り直す.bat` を開きます。
消すのは `runtime` だけです（台帳・名前・モデルはそのまま）。

**「準備する」でモデルが取れない**
`huggingface.co` に届かないときに起きます。ブラウザで次の 2 か所から手で取って置くこともできます。

```
models\head\model.onnx          ← deepghs/anime_head_detection の head_detect_v2.0_s/model.onnx
models\head\model_type.json       （同じフォルダの json も、あれば一緒に）
models\head\threshold.json
models\ccip\model_feat.onnx     ← deepghs/ccip_onnx の ccip-caformer-24-randaug-pruned/ の 4 つ
models\ccip\model_metrics.onnx
models\ccip\metrics.json
models\ccip\cluster.json
```

置いたらキャラ帳の設定で「試験をやり直す」を押してください。

**GPU で動かない（CPU になっている）**
設定の「解析に使う装置」に、GPU ごとの試験結果と使えない理由が出ます。
グラフィックドライバを更新してから「試験をやり直す」を押してください。CPU でも動きますが、全件の解析は遅くなります。

**画面に「版が違います」と出る**
ファイルの差し替え漏れか、古い画面が残っています。想起の窓を閉じて `起動.bat` を開き直し、
ブラウザで `Ctrl+F5` を押してください。

**「メタ無し」と出るファイルがある**
PNG にワークフローが埋まっていません（メタデータを消した、別のツールで保存し直した等）。台帳には載りますが再投入はできません。

**「ComfyUI の画面で開く」を押しても ComfyUI に出ない**
受け口を入れたあと、ComfyUI を再起動しましたか。再起動のあとは、ブラウザの ComfyUI の画面も読み直してください（F5）。
ComfyUI の起動の表示の `Import times for custom nodes` に `souki_bridge` が出ていれば入っています。

**ランプが全部灰色のまま**
ComfyUI が起動していないか、`config.json` の `comfy_url` が違っています。

**C から K へ画像を退避した**
「更新」を押せば追従します。ファイル名とサイズが同じ記録は **移動として検出** し、読み直さずにパスだけ書き換えます。
キャラの確定もそのまま残ります。**名前を変えたり、メタデータを消して保存し直したりした絵** も、
絵柄（dHash）と大きさが同じなら確定を引き継ぎます。

**K ドライブを繋がずに更新してしまった**
**到達できなかったフォルダの記録は消しません。** 繋ぎ直して更新すれば元通りです。

**前の版に戻したい**
`_旧版` に前の版の部品があります。台帳と前の版のデータは（消していなければ）そのまま残っています。

## 6. 検証状況

作業環境から Hugging Face にも Windows の GPU にも届かないため、**本物のモデル・DirectML・RTX 5080/3060 では動かせていません。**
代わりに次のことを確かめています。

- **前処理・後処理が元の実装（dghs-imgutils）と同じ計算になる**こと（画像を使った突き合わせ）
- 本物と同じ入出力の形をした **試験用のモデル** で、台帳 → 試運転 → 全件解析 → 候補 → 名前付け → 判定 → 確認待ち 3 周 → 取り消し、が通ること
  - 自動で入った顔に別の子が混ざらない（色だけ違う 2 人も取り違えない、2 人の絵の顔 80/80、一度きりの顔 0/120）
  - 判定を何度やり直しても結果が同じ（悪循環が起きない）。覚えた近さを使った判定と一から計算した判定が同じ
  - 取り消しで完全に元に戻る
- 差の式（CCIP の差を出すモデル）の形を 4 種類用意して、どれでも正しく見分けられること
- **顔 15 万個** の模擬データでの速さ（2 コアの作業環境。要平さんの PC ではもっと速いはずです）

  | 処理 | 時間 |
  |---|---|
  | 候補づくり（15 万個から） | 約 18 秒 |
  | 最初の判定（80 人に名前を付けたあと） | 約 13 秒 |
  | ふだんの操作のあとの判定 | 約 4 秒 |
  | 見本が全員分入れ替わったとき（80 人 × 見本 400） | 約 70 秒 |
  | 確認待ち・未分類・キャラ一覧の表示 | 0.1 秒以下 |

- **要平さんの台帳と同じ大きさ**（画像 12 万枚・顔 12 万個、いちばん大きい候補 3 万 4 千枚）の模擬データで、
  画面の操作ごとの時間を測りました（同じ 2 コアの作業環境）

  | 操作 | v2.0 | v2.1 |
  |---|---|---|
  | 画面の状態の問い合わせ（前の版の顔の切り抜きが 12 万ファイル残っているとき） | 1.1〜2.3 秒。画面を開くたび・操作のたびに毎回 | 0.1 秒以下（起動時に裏で 1 回だけ数える） |
  | 名前付けのあとの判定（何も変わらないとき） | 1.8 秒 | 0.3 秒 |
  | 候補 3 万 4 千枚を最後まで見る | 「さらに表示」（50 枚）を約 670 回 | 1000 枚ずつなら 34 ページ。かたまり表示なら数十のかたまり |
  | 見ていない顔も含めて × 以外を確定 | できない（表示した分だけ） | 「全部」で 0.3 秒（そのあとの判定は裏で数秒） |
  | 候補を開く（かたまり表示） | — | 約 1 秒 |
  | 並べ替えを変える／次のページ（1000 枚） | — | 0.3〜0.6 秒 |
  | キャラの画面のタブを切り替える（確定 3 万 4 千枚） | — | 0.5〜1.5 秒 |
  | 取り消し（3 万枚の確定） | — | 0.1 秒 |


  Windows のフォルダは Linux より数えるのが遅いので、要平さんの PC では v2.0 の「状態の問い合わせ」はさらに長くかかっていたはずです。

  候補の中の「かたまり」は、模擬データでは 1 つのかたまりに別の子が混ざることはありませんでした。
- まとめて × を付けたときに本人の顔が少し混ざっても、そのキャラの自動が丸ごと止まらないことを確かめました
  （混ざった × の近くの顔は「否に近い」で確認待ちに回ります）
- 画面は実際のブラウザ（Chromium）で一通り操作して確かめました
- v2.3 の投入まわりは、本物の ComfyUI で確かめました：ComfyUI を数秒止めて「返事待ち」になってもボタンが押せ、
  止まっている間に押した投入も、ComfyUI が戻ると届くこと。できた PNG に画面用のワークフロー（`%date%` のひな形・差し替えたプロンプト入り）が入り、
  `2026-10-4/2026-10-4illu名前_00001_.png` に保存されること。服装・強さ・名前を聞く窓・服の登録は画面で操作して確かめました
- 「ComfyUI の画面で開く」は、作業環境で本物の ComfyUI（2026 年 9 月の最新版、CPU で起動）に受け口を入れて確かめました。開いている画面への読み込み、画面が開いていないときの預かり、キャラの差し替え・今日の日付の反映、受け口が無いときの一覧への保存
- bat ファイルは ASCII だけ・CRLF・複数行の `if (...)` なし（前に cmd.exe でつまずいた書き方を避けています）

**本物のモデルでの見分けの精度は、試運転の画面ではじめて分かります。** 試運転の「見分け」が
「見分けが苦手な絵柄です」と出たり、候補に別の子が多く混ざっていたりしたら、そのまま知らせてください。
